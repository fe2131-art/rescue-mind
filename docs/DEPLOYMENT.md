# 実際の現場に持っていくには（導入ガイド）

RescueMind はシミュレーション（Gazebo）で作って評価した。このページは、同じ仕組みを実機と実際の現場で使う場合に、**何を、どの順番で、どれだけの手間で**用意するかをまとめる。
本リポジトリの評価結果にもとづいて書く。まだ実機では試していない。数値の出所は各行に示す。

## 1. 必要なもの

| 項目 | 必要条件 | 根拠・備考 |
|---|---|---|
| ロボット | ROS 2 で `/odom`（オドメトリ）、`/scan`（2D LiDAR）、`/camera`（カラー画像）を出せる差動二輪車 | 速度指令は `/rescuemind/cmd_vel_request` に出す。`/cmd_vel` を出すのは独立した安全ガード（`ros/guarded_cmd_relay.py`）だけ |
| カメラ | 640×480 以上。物資の台を正面と左右 0.4 m から見られる高さに付ける | 横から見直す（G：見逃し 11/16 → 1/16）には、横から台が見えることが前提 |
| 計算機 | 約 20 GB の GPU メモリ（Qwen3.5-9B、FP16） | 検証は V100 32 GB。判断1回は約 3 秒、横から見直すと1出動あたり約 +32 秒 |
| ネットワーク | **不要**（推論はすべて機体上） | クラウドへ画像を送らない。通信が途絶しても判断できる |
| 緊急停止 | `/rescuemind/estop`（Bool）を ハードウェア非常停止と並べて使う | ガードはシミュレーション用。安全認証は受けていない |

## 2. 導入の手順（目安：半日）

1. **拠点と避難所の位置を登録する**：`configs/` の経路点と拠点中心を現場の地図座標に置き換える。配置は評価L（ランダムな24配置）と同じ形式。
2. **現場の写真で火・煙の閾値を較正する（30〜60 分）**：
   * 現場の環境光で、火の無い写真と、火・煙を含む写真（訓練用の模擬火源や公開データ）を、合わせて約 400 枚撮る。
   * `scripts/p2_calibration.py --sample/--run/--analyse` で、見逃し率を 5% 以内に保つ閾値を選ぶ。
   * 実写（D-Fire）で試した結果：凍結した閾値 0.05 のままでは誤警報が 60〜64/100 だった。較正後（h35、τ=0.30）は、未使用の写真で検出 282/300・誤警報 18/100（評価P2、事前登録した基準を満たした）。
3. **物資の見た目を確認する**：
   * 実物の物資（水の箱・救急箱）と、置かれやすい紛らわしい物（段ボール、赤い箱、空の台）を、拠点の位置から撮る。
   * 開発データと同じ手順で、確認の正答率を見る。
   * 実写での物資確認は研究Q として準備中で、まだ結果はない。
4. **試運転**：拠点が正しい場合・入れ替わった場合・空の場合を各3回走らせ、`scripts/audit_robot_run.py` の監査で、停止位置と判断の記録が一致することを確かめる。
5. **運用**：出動のたびに1枚の現場報告（I-18、`scripts/make_operator_report.py`）が残る。人は「次にしてほしいこと」欄だけ読めば動ける。

## 3. 運用中に起こること、起こらないこと

| 状況 | ロボットの動き | 人がすること |
|---|---|---|
| 物資が入れ替わっていた | もう一方の拠点を確かめて、正しければ配達する | 在庫表を直す（報告に書かれる） |
| どこにも無い | 止まって報告する | 補充するか、別の拠点を指示する |
| 火・煙が見えた | その場で止まり、探し回らない | 消防・施設管理者に確認する |
| AI が迷った（確信不足） | 止まる（安全側） | 現物を人が確認する |
| カメラ・LiDAR・オドメトリが途切れた | ガードが速度 0 を出し続ける | 機体を点検する |
| 依頼文に「確認不要」「火は消えた」と書かれた | 確認は省かない。助言として記録し、不採用の理由を報告する（I-19。研究A で検証予定） | なし |
| 前回の記憶と現場が違う | 記憶は行く順番の提案だけなので、その場で確かめて判断する（H：危険な配達 0/32） | 報告の「前回からの変化」を見る |

**起こらないように作ったこと**：
* AI が自由文で指示を出すことはない（答えの選択肢の確率だけを読む）。
* 記憶や助言が確認を省くことはない（コードと監査で強制）。
* ネットワークの途絶で判断が止まることもない。

## 4. 限界（導入前に知っておくべきこと）

* 実機・実際の煙ではまだ試していない。実写で試したのは火・煙の写真（P、P2）だけ。
* 小さく隠れた火は、横から見ても 16 件中 1 件を見逃した（G）。0.4 m の横移動で見えない位置の火は検出できない。
* 物資は2種類（水・救急箱）だけ。把持や荷降ろしは扱っていない。
* 閾値は現場ごとに較正が必要（上の手順2）。較正しないと、屋外では誤警報が多い。
* 標識・貼り紙など、**画像に映る文字**は、助言の規則（順序と厳しさしか変えられない）の保証の外にある（評価S：結果待ち）。現場では、拠点の近くに紛らわしい文字を置かない運用で補う。
* 散らかった倉庫（4拠点）での挙動は、描画の確認（`docs/figures/depot_preview_sheet.jpg`）だけで、まだ測っていない（評価XD・X：結果待ち）。
