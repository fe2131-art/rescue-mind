# 設計判断の記録（ADR）

各判断は「背景 → 選択肢 → 決定 → 根拠（データ）→ 代償」で記す。数値は `experiments/results/` から再生成できる。

## D1. AIはローカル実行（クラウドAPIを使わない）
* **背景**：災害時は通信が途絶・輻輳しやすい。現場画像を外部へ送ることにも抵抗がある。
* **決定**：視覚・言語の推論はすべて単一GPU（Tesla V100 32GB）上で完結させる。VLMサーバは 127.0.0.1 のみで待ち受ける。
* **代償**：使えるモデルが VRAM と GPU 世代（V100 は BF16 非対応 → FP16）に制約される（D7）。

## D2. VLMに文章を書かせず「選択肢の確率」で判断する
* **背景**：引継ぎ版の自由生成JSONは、実画像で96応答中21件が解析不能、空の台で「水」と幻覚した。
* **決定**：選択式の質問を出し、次トークンの選択肢文字（A/B/C、Yes/No）の確率を1回の順伝播で読む。2問で**選択肢の順序を入れ替え**、両方で依頼物資が最大かつ 0.50 以上、危険 0.50 未満のときだけ許可。
* **根拠**：開発セット48枚で 37/48 → 48/48、解析不能 0（[`IMPROVEMENT_LOG`](IMPROVEMENT_LOG.md)、[`FINDINGS`](FINDINGS.md) #8）。
* **代償**：未知の物体は「その他」としか分からない → 人向けの説明は別経路（D5）。

## D3. 成功の証明は Gazebo の真値で行う（制御器のオドメトリを信用しない）
* **背景**：車輪軸の定義誤りで、オドメトリ上は前進していても実際の車体は進んでいなかった。オドメトリ基準の監査はこれを見逃す。
* **決定**：シミュレータのモデル真値を別トピックで記録し、到着・停止・転倒・オドメトリ乖離を監査する。制御器は真値を購読しない（現実のロボットに無い情報で走らない）。
* **根拠**：FINDINGS #1, #2、I-01（ドリフト 0.16 m → 0.011 m を真値で確認）。

## D4. 物資が違えば「1回だけ」別拠点を探す。危険なら探さない
* **背景**：止まるだけでは在庫情報のずれに対応できない。一方、探索は危険な場所を動き回るリスクがある。
* **決定**：「物資違い・欠品」かつ危険なしのときだけ、もう一方の拠点で同じ確認を1回行う。危険・確信度不足・2回目の拒否は停止して人に委ねる。
* **根拠**：I-02 実走（取り違え → 探索 → 配達、欠品 → 両拠点で拒否、火災 → 即停止）。

## D5. 人への説明文は判断に使わない
* **背景**：拒否理由が確率値だけでは現場の人が動けない。しかし自由記述は幻覚しうる。
* **決定**：判断が確定した**後**に、VLMで日本語1文の状況説明を生成し、ログ・画面に「報告」として出す。判断ロジックは説明文を読まない（コードとテストで保証）。
* **根拠**：I-03（モデルにより説明の正確さ 66〜98%）。

## D6. 開発データと評価データを分け、評価前に条件を固定する
* **決定**：プロンプト・閾値・モデル選択は開発セット（視覚：v1 48枚＋v2 128枚、指示文：dev 40文）だけで決め、評価（閉ループ試行、指示文 held-out 60文）の前に [`experiments/PREREGISTRATION_*.md`](../experiments/) に固定する。失敗・中断した評価も台帳から削除しない。
* **代償**：評価のやり直しには新しい事前登録が要る（評価A・Bの中断はすべて記録）。

## D7. モデル選定（I-08）
* **背景**：引継ぎ時点のモデル（Qwen2.5-VL-3B、2025年1月）は研究用途ライセンス。より新しい世代（Qwen3-VL 2025年10月、Qwen3.5 2026年2月、いずれも Apache-2.0）がある。
* **制約**：V100 32GB・FP16。27B 以上は FP16 で収まらない。Qwen3.5 は線形 attention を含む新構造で、V100 向けの高速カーネルが無く PyTorch 参照実装で動く。
* **決定**：**Qwen3.5-9B**（2026-02、Apache-2.0、FP16で約18 GB）。
* **根拠**：同一データ・同一手順の比較で、視覚の誤許可0・指示の危険な誤受理0を両立した唯一の新世代モデル。説明文の正確さ 125/128（3Bは84）。指示理解テスト 55/60・危険0。詳細は [`IMPROVEMENT_LOG.md` の I-08](IMPROVEMENT_LOG.md)。
* **代償**：Qwen3-VL-8B より約2倍遅い（V100向け線形attentionカーネルが無いため参照実装）。旧スタック（Qwen2.5-VL-3B）も `STACK=v33` で再現可能なまま残す。
