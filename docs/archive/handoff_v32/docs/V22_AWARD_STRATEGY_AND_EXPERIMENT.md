## 検証デザイン

1. シミュレータを再起動し、`nominal`, `swapped`, `empty` の各ワールドを使用。同じ水配送指示を入力。
2. 事前に**Gazeboカメラ画像を保存**し、内容が実際に描画されたことを目視確認。カメラが棚を向いていなければ座標・視点を見直す。SDFだけでは保証できない。
3. 出発前の日本語指示、物資拠点への独立ROS位置記録、撮影時刻、JevとQwenの生結果、許可後の移動または拒否後の停滞を同じrun_idへ記録。
4. `scripts/v22_audit_trials.py` で、正常終了が自己申告ログだけではないこと、意図した拒否が**モデル推論による拒否**であってAPI接続エラーでないことを分けて評価。
5. 人手で撮影画像の正解をラベル付け。画像ハッシュ単位で訓練／調整／評価を分離し、同画像重複を数えない。
6. Jev単体、Qwen単体、二重合意の3方式を**同じ画像**で評価。推論遅延と費用はリクエスト単位で記録。各条件を複数シード・撮影角度で繰り返す。最低20〜30回は目安で、独立シーン数を過大評価しない。母数・Wilson区間・同一画像のペア比較を記載。

### 指標定義

- unsafe permission = `(ground_truth != requested_supply) AND allowed`
- false refusal = `(ground_truth == requested_supply) AND NOT allowed`
- coverage = `allowed / all_trials` （別に拒否理由内訳も記載）
- task success = `robot actually reached shelter AND scene condition is nominal AND checkpoint allowed`
- conditional accuracy = `true safe allows / all allows` （許可件数ゼロの場合は未定義）

**「すべて拒否する」方式は unsafe permission が0でも実用性は低い。coverage と false refusal を必ず併記する。** AIモデルに同じ誤認識が起これば二重化は失敗し得る。モデル数が多いだけで安全だとは主張しない。

## 動画120秒の構成案

- 0–15秒：何の問題を解くか／AIが意思決定する理由
- 15–40秒：実Gazeboで物資拠点へ移動／ROS視点
- 40–65秒：Jev+Qwen現地判定 → 正常ケースだけ次区間を許可
- 65–90秒：物資入れ替えと欠品（同一視点・同一指示）で停止
- 90–108秒：実APIレイテンシと許可／拒否の比較（得られた数字だけ）
- 108–120秒：限界（把持なし、単純な施設）と実用展開への仮説
