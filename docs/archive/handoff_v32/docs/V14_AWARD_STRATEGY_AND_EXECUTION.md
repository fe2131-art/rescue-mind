| 課題の加点要素 | 作品上の独自貢献 | 最終提出に必要な実測の証拠 |

| 創造性 | 「物資棚に接近→現地撮影→JevとQwenで再判断→次の行動が変わる」閉ループ | 同一走行環境で**正しい物資**の走行継続と**別物資／不一致**の停止 |

## 初回実行（Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic）

```bash
cd rescuemind_v14
bash scripts/check_ubuntu_ros.sh
bash scripts/setup_ubuntu_jazzy.sh
bash scripts/v14_verify.sh
python3 scripts/v14_orchestrate.py --plan --scenario motion-check
python3 scripts/v14_orchestrate.py --run --scenario motion-check
```

この単一コマンドは実際にGazebo・ROSブリッジ・ガード・ミッションを起動する予定で、必要条件を満たさなければ停止する。`--plan`は実行計画の検査のみ。ログは`outputs/runs/<stack_run_id>/`。

実AIは認証情報を環境変数に設定した後、次のコマンドで実行する。**資格情報をコマンドライン引数やGitHubへ書かない**。

```bash
python3 scripts/v14_orchestrate.py --run --scenario live --instruction '避難所Bに飲料水を届けて'
```

> `--run` はユーザーのローカルUbuntu PCに依存。こちらの検証コンテナには`ros2`と`gz`がなく、実走行の動作保証はできない。

## モデル比較の最低限の実験表

- **データセット**：ラベル済みの新規Gazeboカメラ画像。物資種類が均等で、見えない画像・見間違いやすい物体・遮蔽を含む。元画像のSHA-256と撮影時刻を保存。
- **評価モデル**：Jev単独、Qwen単独、Jev＋Qwen二重許可。
- **評価**：誤許可率（unsafeを許した割合）、誤拒否率（safeを拒んだ割合）、推論遅延、障害物による停止、移動完走率。
- **注意**：人工条件での判定率を本物のAI認識性能と混同しない。同じ試行の同じ画像で3方式を比較する。ハイパーパラメータは検証用データで固定し、試験画像で調整しない。
