# 優秀賞を狙う戦略｜v1.6

**企画**：RescueMind ― JevとQwenの視覚的な二重判断で、物資拠点で「進む／停止」を切り替える救援ロボット。物資を把持・搬送するわけではなく、物資拠点確認と避難所への接近を実行する。

| 課題評価軸 | 証明する内容 | オフラインで完了 | 最優先の実機相当課題 |
|---|---|---|---|
| 創造性 | 同じ指示でも現地の画像が違えば移動が分岐 | AIゲート・状態管理 | 正しい物資/間違った物資の2パターンを録画 |
| 技術力 | AI→ROSカメラ→走行制御の因果関係 | 継続オドメトリ監視・実行ログ検証 | Gazebo/Harmonic実走行、ROS bridgeとの整合 |
| 実用性 | 誤許可率と誤拒否率、途絶検出 | 人工入力故障テスト | 実画像の正解ラベル付きペア比較と推論時間 |
| 表現力 | 2分動画で出発・判断・継続/停止を明示 | 提出原稿・ログ機構 | MP4を撮影、PDFに数値と限界を書く |

## 先に完成させるべき順番

1. Ubuntu 24.04で`motion-check`の本物のGazebo動画を録る。
2. Gazeboカメラ画像が水/救急箱を写すことを目視確認。
3. Jev 1.14とQwen3.8を実画像で各1回ずつオンライン実行。
4. 合意→避難所へ進む、否認→物資拠点で停止する2場面を再現。
5. 同じ画像を各モデルで評価し、人手正解ラベルと比較する（誤許可と誤拒否、遅延、失敗理由を併記）。
6. MP4(60–180秒)、GitHub public、PDF、YouTube URLを仕上げる。

## 2分動画のシナリオ

0–15秒 課題/環境、15–35秒 指示、35–60秒 拠点へ走行、60–85秒 Jev/Qwen画面の実応答と続行、85–110秒 不一致時停止、110–120秒 実測/制約。
