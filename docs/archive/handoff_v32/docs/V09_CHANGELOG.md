# 改善サイクル v0.8 → v0.9

| 問題の発見 | 修正 | 実行検証 | 残課題 |
|---|---|---|---|
| 現地で物資が正しいと、同一画像に危険が映っていても避難所へ進める | Jev hazard/sceneとQwen sceneの拒否条件、欠損/不正値拒否 | `tests/test_v09_improvements.py`、972条件 | 危険ラベル精度/誤拒否率はAPI実画像で要検証 |
| 前進命令でもロボットが動けないと制御継続 | `ProgressWatch`の停滞検知を直接駆動に組込み | 時間逆行・正常前進・旋回・永久停止の単体テスト | Gazebo摩擦/タイヤ接地での実測 |
| AIライブモードの出発前にカメラ不通を検出できない | warmupでROS画像必須 | 模擬ROS/静的検査 | ROS実カメラのフレーム・品質 |
| ログ中にQwenの実応答がなくても監査通過可能 | Jev+Qwenの識別子/自己報告、結果再計算、イベント時系列を監査 | 模擬ログの改ざん故障注入 | ログは自己申告であり映像による独立検証が必要 |
| 人工ロジックに偏りがあり比較困難 | 972条件の全組合せを分布付きで保存 | `outputs/release/v09_fault_matrix.json` | 実際の画像と人手ラベルを集める |
| ローカルでの動作診断が手動手順だけ | ROS受信診断、X11用生録画スクリプトを追加 | シェル構文・引数の検査 | ROS/Gazebo/X11での実行確認 |

**重要**：今回のテストが増えても、受賞要件の「ロボット実行動画」を達成したことにはならない。最優先のブロッカーは本物のGazebo+Jev+Qwenを同じ試行で動かすこと。
