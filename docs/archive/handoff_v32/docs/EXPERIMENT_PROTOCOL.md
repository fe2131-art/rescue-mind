# 事前登録する比較実験計画

## 研究仮説

H1: Jev + Qwen3.8の合意ゲートは、どちらか単独より誤許可率を下げる代わりに棄却率を高める可能性がある。
H2: 動的障害物へのNav2迂回は固定経路より到達率を高める可能性がある（これはVLM改善の直接証拠ではない）。

## データ収集設計

- 物資: water/medicine/other、通路: clear/hazard/unknown。組合せと照明、距離、向き、遮蔽を分層する。
- 最低目標60例、可能なら120例（各クラス偏りを抑える）。明白なパターンだけではなく視認不能例を意図的に入れる。
- 認識に入力する画像（物資/通路）は異なる画像・場面。人間が物資と通路を事前にラベル付け。
- 公開データ/人工画像は別セット。人工パターンの精度は実機の性能を代表しない。
- 同一の画像組をJevとQwenに入力。モデルID・閾値・API日時・レイテンシを記録。
- モデルやプロンプト選定時の調整データと最終テストセットを分ける。テストセットのラベルを見ながら閾値最適化しない。

## 選択的分類を含めた指標

- **coverage:** 許可数 / 全例数（高いほど配送しやすい）
- **unsafe_approval_rate:** 誤物資または危険通路に対して許可を出した件数 / 全例数（低いほど良い）
- **precision_when_approved:** 正しい物資かつ安全な通路に対する許可数 / 許可数
- **false_denial_rate:** 正しい物資・安全な通路にもかかわらず棄却 / 全例数
- 平均応答時間・p50/p95・API課金・通信失敗率は独立した補助指標。
- 母数n、真の安全ケース数、Wilson 95%区間を集計。信頼区間は独立ケースの二項近似であり、同じ背景を撮影した相関サンプルでは過信しない。少数例の百分率だけで優越を主張しない。

## 比較条件

A: Jev単独、B: Qwen3.8単独、C: Jev+Qwen3.8合意ゲート。閾値は学習/検証集合で先に固定。全方式に同じ画像セット。

D: ROS/Nav2での静的障害物なし、E: 同じマップ・ゴールで障害物追加。経路変化が起きたか、到着と衝突回数、超過時間を計測。D/EはAI視覚性能ではなく走行系を評価。

## データ出力

`python -m rescuemind.record_real_case`で1例ずつ実推論を実施、真値付きJSONL保存。`python -m rescuemind.benchmark_vision --records ...`で集計。モデル実行がない間は全指標を**未計測**と表示する。

## バイアスとリスク

- モデル判定が相関していると、2モデル合意でも誤許可が残る。
- 知覚評価が高くても、カメラ位置・Nav2地図・障害物座標などの問題で配送は失敗し得る。
- Jev Boxは画像平面の位置のみ、2D→3D距離/地図上の危険座標は推定しない。
- 画像AIはスナップショットによる**走行前**ゲートのみ。走行中はLiDAR距離/センサタイムアウト/E-stopによるNav2取消コードを追加したが、本物のROS環境での検証はまだない。
