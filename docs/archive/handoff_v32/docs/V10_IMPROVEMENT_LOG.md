# 改善→実行→分析→修正: v0.9 → v1.0

## ループ 1: カメラ画像の鮮度
**発見**：`on_camera`でROSメッセージの受信時刻だけを見ていたため、Gazeboの古い撮影画像が遅延配信されても「現地撮影」と誤認する余地があった。
**修正**：`rescuemind/frame_freshness.py`で`header.stamp`（ROS撮影時刻）を読み、到着前のstampより厳密に新しく、さらに停止後0.5秒の受信である画像のみ判定。欠損、ゼロ、タイムスタンプ逆行を拒否。逆行はラッチ。
**検証**：新鮮/古い/逆行/ゼロ/欠損の回帰テストと、模擬ROSの走行経路テスト。実Gazeboの時刻設定までは未検証。

## ループ 2: ログは映像の証拠とは限らない
**発見**：JSONログが`real_model: true`と主張しても、画像バイト列や動画の長さと照合していなかった。フラグは真正性の証明ではない。
**修正**：`scripts/build_evidence_bundle.py`を作成。ログ監査と実際の画像ファイルsha256、MP4 ffprobe duration/codec（60–180秒）を検査し、満たさなければ証拠ZIPを拒否する。
**検証**：画像改ざん/60秒未満/180秒超/タイムスタンプ欠落/監査失敗をテスト。API真正性と実Gazebo撮影は目視・手動検査が必要。

## ループ 3: 表現力と提出
**発見**：旧バージョンはテストの数が多い一方、提出物の未達が残っていた。
**修正**：採点4軸に対する動画・ログ・比較実験の証拠対応表を追加。新しい一次資料調査、Ubuntu実行手順、PDFドラフト作成。モデルの実測値は捏造しない。
**検証**：PDFテキスト抽出・画像レンダリング、ZIP新規展開からのテスト、SHA-256一致で検証する。
