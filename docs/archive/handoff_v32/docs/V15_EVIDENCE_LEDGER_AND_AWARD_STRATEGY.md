## なぜv1.5で「起動前に3枚/3スキャン/3オドメトリ」を確認するのか

v1.4ではreadinessの根幹が「一度トピックがechoできる」こと。これでは、古い画像・ゼロstamp、無効なクォータニオン・LiDARレンジ、壊れた画像バッファを見落とす。v1.5は**3回異なる収集時刻のデータ**と基本形式を確認する。これに通過したときだけロボットの走行を開始する。外部環境の可用性とキャリブレーションは依然として未検証。

| 評価軸 | v1.5の設計上の貢献 | 審査に示すべき実測 |
|---|---|---|
| 創造性 | 言語指示→現地観測→Jev＋Qwen一致/不一致で続行/停止 | 同一条件での分岐シーン |
| 技術力 | ROS2カメラ/レーザー/オドメトリの品質チェック、二重判断・独立速度ガード | トピック実データ・撮影時刻・停止判断の同期ログ |
| 実用性 | 不確実なデータで走行を許さない・通信異常時の保守的動作 | safe/unsafe評価における誤許可・誤拒否・停止時間 |
| 表現力 | 1〜3分実シミュレータ動画、因果ログ＋評価グラフ | 現地画像・判断テキスト・走行映像の同期 |
