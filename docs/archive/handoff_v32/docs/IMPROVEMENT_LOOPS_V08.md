# v0.7 → v0.8 再現可能な改善ループ

| 問題点 | 修正 | 今回の確認 | 限界 |
|---|---|---|---|
| 事前に2枚の静止画を手動準備しなければ実行できなかった | `--run-live`追加：TF-IDF指示分類で物資拠点→ROSカメラ実フレームで**必須Jev＋Qwen**判定→避難所 | fake ROSモデルの許可/拒否で次区間の動作が変わる | 本物のROS/Gazeboカメラ/APIは未実行 |
| 指示文が曖昧でも二択を強制した | `decide_intent`で複数物資・未知・未対応避難所・低スコアを事前拒否 | 単体テスト | 40例で学習したTF-IDFのスコアは未校正 |
| LiDAR無検出の`+inf`で誤停止する | `+inf`をrange_max扱い、NaN/全データ欠落は停止 | 単体テスト | Gazebo実走行は別途要確認 |
| BoxのconfidenceがNaNでも受理された | 0〜1の有限値に制限 | Jev応答解析テスト | 実験的Boxの認識精度は未検証 |
| ロボットの視野に物資が入るか未計算 | SDFに定義されたカメラFOVと車輪運動学の停止角を静的チェック | 水/医療拠点両方の理想近似で視野内 | 実画像レンダリング不可、縦FOVや遮蔽未検証 |
| 合意型がどう行動を減らすか見えづらい | 108条件の**人工ラベル**で無条件/単独/二重ゲートを比較 | 契約レベルの論理検証 | 実モデルの精度/誤許可率とは無関係 |

今回の結論：優秀賞への最短ルートはコード行数やモックテスト数を増やすことではなく、**実Gazebo映像と実Jev＋Qwen推論で、物資拠点での継続/停止の因果関係を示すこと**。残る作業はdocs/V08_EXECUTION_AND_VERIFICATION.mdのUbuntu現地実行。
