# v0.7 改善ループ／実際の検証

## ループA｜AIがロボットに影響していることを可視化する
- **問題**：v0.6は出発前の画像2枚の許可判断のみ。途中の物資認識が失敗しても2つ目の移動を始め得る。
- **仮説**：拠点到着後のカメラをJev必須＋Qwenで確認すれば、予期せぬ物資違いに対して次の移動を拒否できる。
- **実装**：`rescuemind/checkpoint.py`、`ros/gazebo_waypoint_mission.py`の`onsite_check`。初期のJev＋Qwenゲートと現地ゲートを二段階に分離。
- **検証**：閾値、対象違い、Jev/Qwen省略、モデルID違い、存在確率欠損、偽ローカルROSの成功/拒否を自動試験。模擬ROS走行は本物のROS/Gazeboではない。
- **残課題**：簡素なSDF物資を本物のJev/Qwenが認識するか、Gazeboブリッジでカメラフレームが来るか未測定。

## ループB｜API待機中の見かけ上の安全性
- **問題**：AIをROSメインスレッドで同期呼出するとゼロ速度が送れず、LiDARを購読しない時間が生じる。
- **実装**：AIをdaemonスレッドで呼び出し、ROSメインスレッドは`spin_once`・ゼロ速度送信・LiDAR/odom検査を続行。タイムアウト時は停止。
- **検証**：モックROS駆動によりゼロ速度発行とステージ中断を確認。
- **制限**：ROS/Gazebo実連携での停止距離や危険回避の保証はない。クラウド呼出はタイムアウト後もdaemon側で残存する場合があるが、結果を動作許可に流用しない。

## ループC｜証拠ログの水増しを防ぐ
- **問題**：`preflight.allow`と到達イベントだけでは、実際に現地でAI判定が発生したことをログから区別しにくい。
- **実装**：現地画像SHA-256、JevモデルID、再判定allow、時系列の順序をログ監査の必須条件に。イベント時刻から字幕の下書きSRTを出力可能に。
- **検証**：ハッシュ差し替え・イベント並べ替え・画像欠如・motion-check混入を拒否するテスト。
- **制限**：SHA-256一致やログ整合性は**改ざん防止・実映像の真贋検証ではない**。外部のGazebo録画・API課金/レスポンスログと合わせて確認する必要がある。

## 研究として報告すべき比較（まだ実数値はない）
- 単一スナップショット vs 二段階ゲート、Jevだけ vs Qwenだけ vs 合意、AI出発拒否で悪いケースを防ぐ割合と良いケースを拒否する割合。
- 実画像は独立した複数場面で取得。サンプル数が少なければ95%区間を併記し、モデルの優劣を断言しない。
- 同じ画像/時刻をラベルを変えて繰り返しても独立試験と数えない。
