# 実機（実シミュレーション）実行で初めて見つかった問題と対策 — v3.2 → v3.3

v3.2 の引継ぎ時点では、コードはオフライン単体テストとROS模擬でのみ検証され（単体テストは現在1419件）、
**本物の Gazebo・ROS 2・GPU 推論は一度も実行されていなかった**。
v3.3 では Tesla V100 上の Docker（ROS 2 Jazzy + Gazebo Harmonic）で実際に動かし、
以下の35件の問題をすべて「再現 → 原因特定 → 修正 → 回帰テスト／実走で確認」した
（#1〜#14 は v3.3〜v3.4 の実走、#15〜#18 は未使用テストセット T1 の作成と閉ループ評価 E〜G の準備で、#19〜#21 は I-15・I-16 と評価F〜Hの記録の見直しで、#22〜#23 は論文の整合性確認と評価Jの実行中に、#24〜#31 は変異テスト・証明の見直し・評価Aの予備走行で、#32 は評価IF、#33〜#34 は評価Aの本走行の結果として見つかった。#35 は評価Sの結果である。#32〜#34 はバグではなく、意図の解析・助言の代償・フィルタの限界の実測で、対策は規則の変更ではなく記述と主張の範囲である）。

## 方法論上の工夫

* **開発セットと評価セットの分離**：プロンプト・閾値は、テレポートで視点をランダム化した
  開発画像48枚（seed=7）だけで決め、`experiments/PREREGISTRATION_v33.md` に固定してから、
  事前登録済みの30試行（自律走行での実撮影）を一度だけ実行した。
* **インフラ失敗と判断失敗の区別**：VLM判断が出る前のスタック失敗のみ1回再試行可とし、
  失敗した試行も台帳（`campaign_ledger.jsonl`）から削除しない。
* **AIの拒否 ≠ クラッシュ**：拒否は「拒否イベント＋2.5秒の停止保持＋真値で拠点から動いていない＋bag確定」
  が揃った場合のみ `COMPLETED_EXPECTED_DENIAL` と分類する。
