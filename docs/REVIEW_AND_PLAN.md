# v3.3 の審査基準別セルフレビューと改善計画

講座の加点要素（創造性・技術力・実用性・表現力）に沿って、審査員の視点で v3.3（タグ `v3.3.0`）を厳しめに評価し、
弱点ごとに改善項目（I-xx）を立てた。各改善の実施内容・計測値・コミットは [`IMPROVEMENT_LOG.md`](IMPROVEMENT_LOG.md) に記録する。

## 1. 強み（維持する）

| 観点 | 内容 |
|---|---|
| 技術力 | 実 Gazebo / ROS 2 / GPU 推論の閉ループ。真値監査・独立速度ガード・事前登録評価・失敗の全件公開 |
| 実用性 | 「間違っていたら動かない」既定動作、オフライン完結（クラウド不要） |
| 表現力 | 実レンダリング映像＋確率バー＋真値軌跡のAR合成、倍速の常時表示 |

## 2. 弱点（審査員が突きそうな点）

| # | 基準 | 弱点 | 影響 |
|---|---|---|---|
| W1 | 創造性・実用性 | 物資が違うと**止まるだけ**。現場では「では正しい物資はどこにあるか」を自分で探して届けてほしい | 「安全だが役に立たない」と見られる |
| W2 | 実用性・表現力 | 拒否の理由が確率値だけで、**人への説明**（何が見えたか）がない | 現場の人が次の判断をしにくい |
| W3 | 技術力・AI | 指示理解が40文の合成データで学習した TF-IDF。言い換え・口語・間接表現（「喉が渇いた人が多い」）への汎化が未評価 | 「AIの活用」がVLM部分に偏る |
| W4 | 技術力 | 車輪オドメトリのみの推測航法で長経路ドリフト0.24〜0.27 m（評価Cの不合格1件の原因） | 制御品質の弱さが数値で見える |
| W5 | 創造性・実用性 | 危険（火災・煙・瓦礫）判定の質問を持つが、**危険シーンで一度も評価していない** | 未検証の機能を主張している状態 |
| W6 | 技術力 | VLMの頑健性が単一照明・単一配置でしか確認されていない | 「たまたま当たる」可能性を否定できない |
| W7 | 表現力 | 動画に音声がなく字幕のみ | 視聴者の理解・印象が弱い |

## 3. 改善計画（優先度順）

| ID | 対応する弱点 | 改善内容 | 成否の計測方法 |
|---|---|---|---|
| I-01 | W4 | 推測航法ドリフトの原因を物理設定・制御で切り分けて低減 | 同一経路での最大オドメトリ誤差（真値比）を Before/After で比較 |
| I-02 | W1 | **代替拠点の探索と回復**：依頼と違う物資を見たら、別拠点を確認しに行き、依頼物資があればそれを届ける（無ければ停止して報告） | 取り違えシーンで「正しい物資を届けられた率」0% → ?% |
| I-03 | W2 | **状況説明の生成**：VLMで「拠点に何が見えたか」を日本語1文で生成しログ・画面に表示（判断には使わない） | 説明文の正しさを全シーンで目視採点 |
| I-04 | W3 | **LLMによる指示理解**：同じQwenで指示文を構造化（物資・行先・確信度）し、TF-IDFと比較。未知の言い換え60文の評価セットを新設 | 指示理解の正解率・誤受理率 |
| I-05 | W5, W6 | **危険シーンと環境ランダム化**：火災・瓦礫シーンを追加、照明・小道具配置・妨害物をランダム化した頑健性セットで再評価 | 危険検出率、ランダム化条件での判定精度 |
| I-06 | 全体 | 改善版（v3.4）で事前登録した評価を再実行（新シーン含む） | 30+α試行の判断精度・監査合格率・届けられた率 |
| I-07 | W7 | 動画をナレーション付きで再構成し、改善の軌跡（Before/After）を見せる | 1〜3分の制約内で全シナリオを提示 |

各改善は独立したコミット（メッセージ先頭に `I-xx`）とし、評価に影響する変更の前後で計測値を残す。

# v3.5 時点の結果分析と、最後の改善方針（2026-10-18）

**方針**：改善を細かく積み増すことはしない。結果から最大の弱点を1つ特定し、そこに集中して、事前登録した未使用データで確認したら打ち切る。

## 結果から分かったこと
| 証拠 | 数値 | 解釈 |
|---|---|---|
| 評価E（60試行、試行ごとにランダムな世界） | 60/60、誤配達0 | 設計した条件の閉ループは上限に達した。同じ条件の試行を増やしても情報は増えない |
| T1：物資の確認 | 拒否すべき332枚で誤許可**0件**。誤拒否4件はすべてカメラ距離0.85〜0.94 m | 物資の判定はほぼ完成。近距離では物資が画面から切れる（実機は約1.4 mで停止して確認する）→ 限界として明記する |
| T1：危険（火災）の検出 | 見えている火の面積が1万画素以上なら **68/69**、1万画素未満なら **1/7** | **残る唯一の重大な弱点は、小さく写った火・煙の見逃し**。登録済みの誤許可5件はすべてこれ |
| 評価Eの火災12件 | すべてはっきり見えていた | 閉ループでは難しい条件（ほぼ隠れた火災）を評価していなかった |

## 最後の改善（この1点だけ）
1. 小さく写った火の検出：
   * 候補A：拡大切り出し（I-11）
   * 候補B：Clef-flash（Cloudflare、Jev 互換の判断モデル、ローカル）を2つ目の判断に加える（I-13。当初計画の「Jev＋Qwen の2モデル判断」の復活）
   * どちらを採用するかは開発データ DH だけで決め、選定規則は先に固定する。
2. 採用した構成と v3.5 を、未使用の T2（事前登録、600枚）で比較する。
3. 閉ループ評価F（事前登録）：ほぼ隠れた火災の条件を含めて、ロボット全体での効果を確認する。
4. 打ち切り：論文・説明資料PDF・動画・README を最終結果で仕上げる。
